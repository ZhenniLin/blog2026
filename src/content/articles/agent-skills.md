上一篇[《agent / harness 云里雾里》](/articles/agent-harness/)里，把 agent 理解成能接任务的 AI 同事，把 harness 理解成让他干得成活的工作系统。

接着就冒出了另一个疑问：skill 又该放在哪里？它显然属于 agent 系统的一部分，但既然 harness 已经负责工具、规则和执行，为什么还需要 skill？

延续前面的类比：**agent 是能接任务的 AI 同事，harness 是他的工作系统，skill 则是供他按需使用的“专业操作手册＋配套资料和工具”。**

Skill 提供某类任务的做法；harness 提供发现、读取和使用这些做法的机制。把“工作方法”和“使用方法的系统”分开看，关系就清楚了一些。

以下按截至 2026 年 10 月查阅的一手资料整理。类比用于帮助理解，具体术语的边界仍要看作者如何定义。

## 1．Skill：把经验整理成 AI 可以反复使用的工作包

假设公司新来了一个同事。他理解能力很好，也会搜索、写文章和做表格，但未必知道：

- 公司习惯怎么做竞品研究。
- 哪些来源可以采信。
- 产品价格应该按什么口径比较。
- 报告需要什么结构。
- 交付前必须检查哪些内容。

可以每次交代一遍，也可以整理成一套“竞品研究工作包”，需要时让他参考。

**Skill 就很像这套工作包：把某类任务的专业知识、操作步骤、模板和辅助程序，整理成可重复使用的资源。**

Anthropic 对 Agent Skills 的介绍，就是把指令、脚本和资料组织起来，让 agent 按需发现和加载。它也用了“给新员工准备入职指南”的类比。[原文：Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

比如，一个“竞品研究 skill”可以包含：

| 组成 | 通俗理解 | 示例 |
| --- | --- | --- |
| 使用说明 | 什么时候拿出这套工作包 | 做产品定位、定价或功能比较时 |
| 工作步骤 | 应该怎样推进 | 先确认比较口径，再收集证据 |
| 专业规则 | 哪些细节不能忽略 | 区分月付与年付、免费版与企业版 |
| 参考资料 | 做事时可以查什么 | 研究方法、术语解释、案例 |
| 输出模板 | 结果应该长什么样 | 对比表、证据链接、待确认事项 |
| 辅助程序 | 哪些操作可以直接执行 | 整理数据、检查必填字段 |

不是每个 skill 都需要包含以上全部内容。最简单的可以只有说明；复杂的可以附带模板、资料和程序。

当前开放的 Agent Skills 格式，核心是一份名叫 `SKILL.md` 的说明文件，外加可选的支持文件。[来源：Agent Skills 官方概览](https://agentskills.io/home)

这里讨论的是这种具体的 **Agent Skills 机制**。其他文章里的“小写 skill”，有时只是泛指 AI 的某种能力，需要结合上下文判断。

## 2．Skill 与 harness：工作方法和使用方法的机制

还是拿公司来类比。

**Skill 像“竞品研究操作手册和配套工作包”。** 它主要回答：遇到这类任务，应该参考什么知识，采用什么方法，按什么标准交付？

**Harness 像“公司给这位同事配备的工作系统”。** 它主要回答：怎样把相关手册交给他？怎样执行搜索和程序？进度保存在哪里？操作失败后怎么办？有哪些权限限制？

把模型、agent 也放进来，四个概念可以这样对应：

| 概念 | 类比 | 主要作用 |
| --- | --- | --- |
| Model | 同事的理解和判断能力 | 理解问题、作出判断 |
| Harness | 工作系统与执行机制 | 组织信息、执行操作、保存状态和控制权限 |
| Skill | 专业操作手册与配套工作包 | 提供某类任务可复用的知识和做法 |
| Agent | 正在承担任务的完整 AI 工作者 | 综合这些能力，围绕目标推进工作 |

**Skill 和 harness 的边界，有“内容”与“使用机制”的区别。**

例如，“价格比较必须注明计费周期”，可以写进 skill；把相关 skill 的介绍放进模型可见的信息里，是 harness 的工作；模型判断需要它，提出读取完整说明的请求，是运行中的决策；执行读取、搜索或配套程序，把结果返回模型，则依赖 harness 和工具。

OpenAI 的官方文档描述过这样的过程：harness 发现 skill，将名称和描述加入上下文，模型再选择相关 skill，读取完整说明和支持文件。[来源：OpenAI Skills 文档](https://developers.openai.com/api/docs/guides/tools-skills)

这也解释了为什么不能画出一棵唯一正确的包含关系树：

**采用广义定义时，skill 可以被算作 harness 的组成部分；采用较窄定义时，harness 是运行机制，skill 是它加载的资源。** LangChain 的宽口径定义就明确把 skills 列入 harness。[原文：The Anatomy of an Agent Harness](https://www.langchain.com/blog/the-anatomy-of-an-agent-harness)

前一篇的公式 **Agent ≈ Model＋Harness** 仍然可以使用；在广义定义下，skill 已经包含在 harness 这一侧，无须再重复相加。

## 3．同一个竞品报告例子里，skill 怎样发挥作用？

假设提出这样的任务：

> 帮我比较这三款产品，给我一份有来源的研究报告。

接下来可以这样协作。

### 第一步：找到适用的方法

工作系统先让模型知道有哪些 skill，比如“竞品研究”“文档排版”“数据分析”。模型判断，这个任务需要参考竞品研究 skill。

### 第二步：读取工作包

它读取说明，了解到：

> 优先使用官方来源；价格注明币种和计费周期；区分已确认事实和推测；无法确认的内容单独列出。

### 第三步：实际执行

模型决定先查哪些页面；harness 和工具负责执行搜索、读取资料，并将结果交回来。

### 第四步：遇到问题时调整

发现其中一家公司没有公开价格，模型结合任务和 skill 的要求，决定继续查官方帮助中心，或在报告中标注“需询价”。

### 第五步：交付前检查

Agent 根据 skill 中的检查要求核对报告；如果工作包附带检查程序，也可以通过执行工具运行它。

这里，**skill 提供可参考的专业做法，模型结合现场情况作判断，harness 支持实际执行。** 三者共同影响最终结果。

很多实现会采用“先看简介，需要时再读全文和附件”的方式，称为 **progressive disclosure，渐进式披露**。很像先翻图书目录，找到相关章节后再细读，不必每次把整座图书馆搬到桌上。[来源：OpenAI 官方说明](https://learn.chatgpt.com/docs/build-skills)

## 4．几个特别容易混淆的地方

### Skill 和 prompt 有什么区别？

它们并不完全分离：skill 的说明被读取后，也会成为模型运行时可见的指令和资料。

区别主要在组织方式。一次性的 prompt，是“这次怎么做”的交代；skill 则把经常复用的交代整理成一个有名称、有适用范围、可附带资料和程序的工作包。

**Skill 可以只有指令，也可以比一段提示词丰富得多。** 开放规范允许它包含操作步骤、输入输出示例、边界情况和配套资源。[来源：Agent Skills 规范](https://agentskills.io/specification)

### Skill 和 tool 有什么区别？

搜索工具能执行“搜索”这个动作；竞品研究 skill 可以说明：

> 哪些问题值得搜索、优先搜什么来源、怎样处理互相矛盾的信息，以及如何整理结果。

Skill 也可以附带程序，帮助完成具体操作。因此，它既可以提供方法，也可以携带实现这些方法的辅助材料。

### 装上 skill，模型就学会了一项永久能力吗？

这里说的 skill，主要是运行时读取的外部工作包，通常不涉及重新训练模型。

更像是：**同事拿到了可随时查阅的手册和工具。** 工作包可以一直保存，但当前任务能否用上，还取决于系统是否提供它、模型是否读取它，以及所需工具是否可用。

### Skill 里的要求，是否一定会被执行？

说明文字可以指导行为，但不能自动保证每次都遵守。

例如，skill 写着“保留原始数据”，属于操作要求；工作系统给原始文件设置只读权限，则是实际限制。配套程序还可以检查结果是否符合要求。

这也是两者的一条重要边界：**skill 可以说明应该怎么做，harness 和执行环境可以把其中一部分要求落实成检查或限制。**

### 没有 skill，还能有 agent 吗？

可以。Agent 可以仅依靠任务指令、模型能力和工具推进工作。

Skill 的价值，是把值得重复使用的经验保存下来，让不同任务、不同运行过程，甚至不同兼容的 agent 有机会复用它。实际效果仍需要验证。

## 5．理解 skill，优先读哪些资料？

建议先读三份，分别解决“为什么需要”“它长什么样”“实际怎样使用”。

重点看一个 skill 包含什么、怎样按需加载。读完就能明白，skill 既是对可复用能力的描述，也有具体的文件组织规范。
